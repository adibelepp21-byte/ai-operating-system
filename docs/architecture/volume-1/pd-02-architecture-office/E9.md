3. Core Maturity Principle
Performance maturity is the demonstrated capability of PD-02 to consistently measure, evaluate, govern, communicate, improve, learn from, and appropriately adapt Architecture performance using reliable evidence.
Dengan prinsip tersebut:
High Performance
      ≠
High Performance Maturity
dan:
High KPI Result
      ≠
High Maturity
Maturity harus dibuktikan melalui capability dan evidence.
 
⸻
 
4. Performance vs Performance Maturity
E2 menjawab:
“Apa yang menjadi dimensi performance PD-02?”
E9 menjawab:
“Seberapa matang system PD-02 dalam mengelola performance tersebut?”
Canonical distinction:
Performance
    ↓
"What results are we achieving?"

Performance Maturity
    ↓
"How capable is our system of managing those results?"
Performance result dan maturity result harus dilaporkan secara terpisah.

17. Initial
Initial menunjukkan bahwa Performance Architecture PD-02 masih:
* ad hoc;
* fragmented;
* reactive;
* dependent on individuals;
* inconsistently measured;
* weakly governed.
Typical evidence:
Informal / Fragmented Evidence
Architecture-specific example:
Architecture performance review exists,
but measurement and review practice
depends heavily on individual initiative.
Initial tidak berarti performance selalu buruk.
Initial berarti performance management capability belum reliable.
 
⸻
 
18. Defined
Defined menunjukkan bahwa:
* performance intent telah ditetapkan;
* measurement definitions tersedia;
* review cycle telah ditentukan;
* ownership telah didefinisikan;
* reporting structure tersedia;
* improvement process telah dirumuskan.
Typical evidence:
Documented Evidence
Architecture-specific example:
Architecture review metrics,
architecture performance definitions,
and reporting responsibilities
are formally defined.
Defined tidak berarti system telah berjalan secara konsisten.
 
⸻
 
19. Managed
Managed menunjukkan bahwa performance system:
* consistently executed;
* repeatable;
* evidence-based;
* governed;
* reviewed;
* tracked;
* controlled.
Typical evidence:
Operational + Repeatable Evidence
Architecture-specific example:
Architecture performance measurement
occurs consistently across review cycles,
findings are recorded,
and improvement actions are tracked.
 
⸻
 
20. Optimized
Optimized menunjukkan bahwa PD-02 tidak hanya menjalankan system secara konsisten, tetapi secara sistematis meningkatkan system tersebut.
Evidence dapat mencakup:
* demonstrated effectiveness;
* systematic improvement;
* optimization;
* risk-prioritized review;
* improved decision usefulness;
* reduced recurring gaps;
* improved measurement quality.
Typical evidence:
Effectiveness + Improvement Evidence
Architecture-specific example:
Architecture performance system is
systematically optimized using trend,
finding, and effectiveness evidence.
 
⸻
 
21. Adaptive
Adaptive menunjukkan bahwa performance system PD-02 mampu:
* sense changing context;
* detect emerging conditions;
* learn from evidence;
* adapt performance mechanism;
* adapt review depth/cadence;
* evolve measurement;
* preserve governance integrity;
* preserve architectural boundaries.
Typical evidence:
Learning + Adaptation Evidence
Adaptive tidak berarti:
* uncontrolled change;
* permanent reorganization;
* arbitrary metric changes;
* bypassing Architecture Authority;
* bypassing Governance Authority.

36. Maturity Bottleneck Principle
Critical Dimension Weakness
        ↓

37. Maturity Ceiling
Setiap level memiliki minimum mandatory conditions.
Cannot reach Defined if:
* performance intent belum documented;
* ownership tidak jelas;
* measurement mechanism belum defined.
Cannot reach Managed if:
* execution belum consistent;
* evidence history tidak tersedia;
* review belum repeatable.
Cannot reach Optimized if:
* improvement masih reactive;
* effectiveness belum diverifikasi;
* system-level improvement belum demonstrated.
Cannot reach Adaptive if:
* learning belum institutionalized;
* controlled adaptation belum demonstrated;
* authority integrity tidak preserved.
 
⸻

78. Success Criteria
E9 PD-02 dianggap berhasil apabila:
1. maturity dapat dibedakan dari performance result;
2. lima maturity level memiliki definisi yang distinguishable;
3. setiap level memiliki evidence expectations;
4. maturity tidak ditentukan hanya berdasarkan KPI score;
5. maturity tidak ditentukan hanya berdasarkan documentation;
6. maturity assessment memiliki confidence;
7. insufficient evidence dapat menghentikan maturity overclaim;
8. critical dimension weakness tetap terlihat;
9. overall maturity tidak menyembunyikan bottleneck;
10. maturity progression membutuhkan demonstrated evidence;
11. maturity regression dapat dicatat;
12. maturity sustainability dapat dinilai;
13. formal maturity review dapat dilakukan menggunakan E9;
14. E8 dapat menerima maturity improvement signal;
15. maturity assessment tidak menciptakan decision authority baru;
16. governance, strategy, architecture, dan operational ownership tetap terpisah;
17. maturity reporting dapat diintegrasikan dengan E7;
18. measurement integrity dari E3 mempengaruhi maturity confidence;
19. architecture-specific evidence dapat digunakan untuk menilai maturity PD-02;
20. maturity model tidak memaksakan PD-02 mencapai Adaptive;
21. maturity assessment dapat diaudit dari claim → criterion → evidence → conclusion;
22. Defined, Managed, Optimized, dan Adaptive dapat dibedakan berdasarkan observed capability;
23. maturity regression dapat memicu reassessment;
24. maturity gap dapat menghasilkan improvement melalui E8;
25. architecture impact tetap kembali ke applicable Architecture Governance;
26. cross-platform evidence tidak memindahkan organizational ownership;
27. maturity assessment tetap mempertahankan authority boundary PD-02;
28. maturity assessment dapat diwariskan sebagai domain-adapted model tanpa mengubah reference architecture dasarnya.
