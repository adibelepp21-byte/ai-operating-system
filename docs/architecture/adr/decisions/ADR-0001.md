# ADR-0001

## Metadata

- **Identifier:** ADR-0001
- **Title:** Correct stale Constitution-ratification reference in Domain Model §8
- **Status:** Approved
- **Proposer:** AI Systems Engineer
- **Approval Record:** Approved by Architect — see Approval Record
  section, below.

## Context

The Canonical Domain Model v1.0 was ratified before the Engineering
Constitution existed. Its §8 (Architectural Boundaries) closes with a
governance-discipline statement written in anticipation of a
not-yet-ratified Constitution. The Engineering Constitution v1.0 has
since been ratified (Status: Canonical). The identical staleness pattern
was already identified and corrected, via direct documentation
correction, in the ADR Framework document and in four scaffold
documentation files (`README.md`, `docs/constitution/README.md`,
`docs/principles/README.md`, `docs/glossary/README.md`). The Canonical
Domain Model could not be corrected by the same direct means, because
Constitution §5 (Semantic Foundation Clause) permits no mechanism other
than an approved Architecture Decision Record to alter it — this ADR is
that mechanism.

## Problem Statement

The Domain Model's own statement about how it may be amended is written
in future/conditional tense that no longer matches the present, ratified
state of AIOS governance. Left uncorrected, the highest-precision
document in the repository contains an internal inconsistency, and one
that has already been corrected in every sibling document that had the
same wording.

## Decision

Replace, in Canonical Domain Model §8 (Architectural Boundaries):

> "this document is subject to the Constitution's future Amendment
> Process once ratified"

With:

> "this document is subject to the Constitution's Amendment Process."

No other content in the Canonical Domain Model changes.

**Explicit confirmation of scope:**
- **No entity changes.** §1 (Canonical Entity List) and §2 (Entity
  Definitions) are untouched.
- **No relationship changes.** §4 (Relationships) is untouched.
- **No ownership rule changes.** §5 (Ownership Rules) is untouched.
- **No lifecycle rule changes.** §6 (Lifecycle Rules) is untouched.
- **No invariant changes.** All 14 invariants in §7 are untouched.

## Alternatives Considered

1. **Leave wording unchanged.** Rejected — violates Documentation
   Principles (Constitution §10), which require that a document not
   diverge from what it describes; the Constitution is ratified, and the
   Domain Model's own text should say so.
2. **Direct documentation correction without an ADR.** Rejected —
   precluded by Constitution §5, which permits no mechanism other than an
   approved ADR to alter the Canonical Domain Model, regardless of how
   administrative the edit is.
3. **Bundle with unrelated documentation corrections** (for example, the
   remaining "(planned)" labels in the root `README.md`). Rejected — this
   is the first ADR filed under the ratified governance system; keeping
   its scope minimal and low-risk makes it a clean, low-stakes first
   exercise of the full ADR mechanism rather than conflating it with
   unrelated, lower-tier corrections that don't require an ADR at all.

## Consequences

The Domain Model's governance-discipline reference becomes internally
accurate and consistent with the ratified Constitution and every sibling
document already corrected. No entity, relationship, ownership,
lifecycle, or invariant content changes. This ADR also serves as the
first end-to-end exercise of the ADR lifecycle, identifier assignment,
storage convention, and validation model defined in the ADR Framework.

## Validation

- **Authority validation:** Proposer standing is valid under Constitution

  (§3.2's default), and Domain-Model-affecting decisions are treated as
  Architect-only regardless of delegation status per the ADR Framework's
  Supersession and Deprecation section.
- **Boundary validation:** No Constitutional Tier content is touched; no
  technology, language, framework, or infrastructure decision appears;
  delegation limits are not implicated since approval is direct.
- **Contradiction check:** No prior Approved ADR exists to conflict with
  — this is the first ADR filed under the ratified governance system.
- **Semantic integrity validation:** This ADR quotes only the

  this document.
- **Entity/relationship/invariant impact review:** Explicitly enumerated
  in the Decision section above — zero entities, zero relationships,
  zero ownership rules, zero lifecycle rules, zero invariants affected.
