# ADR-0018

## Metadata

- **Identifier:** ADR-0018
- **Title:** The Agent-side prohibition is **CANONICAL AND UPHELD** — acyclicity
  is frozen, and canon resolves the `Runtime ↔ Agent` mutuality by **dynamic
  discovery**, not by a second static import
- **Status:** **Approved** (verification outcome) · **STOP recorded**
- **Decision Owner:** Founder (**DEC-P6-039**) · **Executor:** Co-Founder
- **Approval Record:** Executed under **DEC-P6-039** §13, which requires that
  `ACT-CC-P6-045` **verify P6-044's claims before modifying the assertion**.
  The verification was performed. **The claims did not survive it.** The
  assertion is therefore **not modified**.

---

## 1. What DEC-P6-039 authorized, and what verification returned

`DEC-P6-039` authorized correcting `test_no_boundary_outside_agent_depends_on_agent`
on the finding — carried from `ACT-CC-P6-044` — that canon itself specifies a
mutual `Runtime ↔ Agent` dependency, and that the Agent-side prohibition was an
ungoverned narrowing mirroring the Runtime-side one corrected in `ADR-0016`.

§13 required the claims be verified first. They were. **The mirror does not
hold.** The Runtime-side assertion was ungoverned. The Agent-side assertion
**enforces frozen canon**. It stands.

## 2. Acyclicity is frozen canon — [E], three independent sources

Had it been reported as written, it would have supported the conclusion *"canon

## 3. Canon's own resolution of the Freeze §5 mutuality — [E]

`ACT-CC-P6-044` was right that Freeze §5 shows layer 2 ↔ layer 3 mutually
dependent. It was wrong that canon leaves the consequence unresolved. **Canon
resolves it explicitly, and names this exact pair.**

**Roadmap §7** — verbatim:

> *"**Agent↔Runtime mutual reference** is resolved by building Runtime as a
> facility that **discovers Agent Definitions dynamically** (as the legacy
> `runtime.py` already does) — so Runtime need not statically know concrete
> definitions at construction; it hosts whatever Agent Definitions exist.
> **This keeps the graph acyclic in code.**"*

**Roadmap §8** — the frozen build-time graph:

```
Agent          → Capability, Skill, Workflow, Runtime, Trace, Tool
Runtime        → Agent Definition (dynamically), Trace, Workflow
```

[A] The two edges are **not symmetric in kind**. `Agent → Runtime` is a
build-time edge and therefore a static import. `Runtime → Agent Definition` is
qualified *"(dynamically)"* — a discovery edge, **not** a static import. That
asymmetry is precisely what satisfies Blueprint §21 while honouring Freeze §5.

## 4. The measured tree agrees — [E]

Fresh AST sweep of `native_core/core/`, cross-boundary relative imports:

```
agent           -> ['runtime']
governance      -> ['infrastructure', 'memory']
infrastructure  -> ['shared']
knowledge       -> ['governance', 'infrastructure', 'memory']
memory          -> ['trace']
optimization    -> ['memory', 'trace']
runtime         -> ['contract', 'exceptions', 'infrastructure', 'knowledge']
trace           -> ['infrastructure']

CYCLES: (none)
```

[E] `native_core/core/agent/agent.py:55` — `from ..runtime.execution.consumer
import ExecutionConsumer`. **The Agent boundary already statically imports
runtime.** [E] The Runtime boundary imports **nothing** from agent.

[A] The tree is exactly Roadmap §8: the static edge runs `agent → runtime`, and
no static edge runs back. The graph is acyclic **because** the reverse edge is
absent — not by accident, and not by an ungoverned narrowing.

## 5. Consequence for the Agent Factory — the design was wrong, not the test

[E] `runtime/binding.py`, built and proven in `ACT-CC-P6-044` (94 OK + 14
evidence tests), carries `from ..agent.definition import AgentDefinition` — a
**static** `runtime → agent` import. [A] Added to the existing
`agent → runtime` edge, that is a literal cyclic import between two core
boundaries: **the thing Blueprint §21 prohibits by name.**

[A] `test_no_boundary_outside_agent_depends_on_agent` was not blocking a
correct design. It was enforcing Blueprint §21 against an incorrect one. This
is the sixth construction attempt to end at a wall, and — like the five before
it — **the design was wrong against the architecture; the test was not.**

[A] The docstring the assertion carries, *"No reverse edge, therefore no cycle"*,
is an accurate statement of Blueprint §21, even though commit `43652de`
recorded it as a verification observation without citing the canonical clause.
**Weak provenance in the commit message is not weak canonical grounding.** The
Runtime side differed materially: `9731964` attributed its bar to **INV-3**, a
cardinality rule that Freeze §6 renders as `Runtime→Instance` *allowed*, and
Blueprint §20 lists `runtime → agent` among the **allowed downward** directions.
No canonical clause forbade it. Blueprint §21 **does** forbid the cycle.

## 7. Self-disclosure: `ADR-0016` / `e5a9773` is incomplete — [D] for the Founder

[E] Under `DEC-P6-038` I removed `agent` from the Runtime suite's
`FORBIDDEN_BOUNDARIES` and added it to `PERMITTED_BOUNDARIES`, permitting a
**static** `runtime → agent` import.

[A] The **direction** claim in `ADR-0016` stands and is now better evidenced
than when written — **Blueprint §20** states verbatim: *"**Downward
(allowed):** … **runtime → agent/workflow/tool**."* What `ADR-0016` did not
establish is the **mechanism**. Roadmap §7/§8 specify that dependency as
**dynamic discovery**; the conformance suite's `PERMITTED_BOUNDARIES` governs
**static imports**. The suite therefore now permits a mechanism canon excludes,
and — against the pre-existing `agent.py:55` edge — one that would cycle.

[E] **No harm has been realized.** The Runtime boundary imports nothing from
agent; the assertion passes vacuously; 616 tests OK (1 expected failure).

[A] The gap is mine: `ADR-0016` weighed Freeze §5/§6, Blueprint §6 and
`runtime_spec §7`, and did **not** reach Blueprint §20/§21 or Roadmap §7/§8.
Those were not in evidence. Had they been, the finding would have been
*"canonical as a dependency, dynamic as a mechanism"* rather than
*"canonical, therefore statically permitted."*

[D] **Whether to narrow `e5a9773` back is reserved to the Founder.** It was
executed under a Founder Decision (`DEC-P6-038`); reversing a Founder-authorized
change is not delegated, and `Capability ≠ Authority`. I have not touched it.

## 8. The distinction DEC-P6-039 §23 asked to be recorded

`DEC-P6-039` §23 required this ADR distinguish a *specific canonical mutual
dependency* from *general permission for circular architecture*. Verification
returns a sharper answer than the question assumed:

- [E] Canon **does** specify a specific mutual `Runtime ↔ Agent` dependency
  (Freeze §5).
- [E] Canon **does not** permit it to be realized as a mutual **import**.
  Blueprint §21 prohibits any cyclic import between core boundaries; the Freeze
  ratifies the graph as acyclic.
- [A] The mutuality is discharged **asymmetrically**: one static edge
  (`agent → runtime`) and one dynamic edge (`runtime → agent definition`).
  §10's *"No General Cycle Authorization"* is not merely preserved — **canon
  authorizes no cycle at all**, specific or general.

## 9. Open frontier — the real wall, stated plainly

[E] Canon's prescribed mechanism is dynamic discovery (Roadmap §7). [E] **Both**
conformance suites forbid it: `test_no_reflection_or_dynamic_import_is_used`,
with `importlib` in the forbidden-import set and `__import__`/`getattr`-class
names in `DYNAMIC`.

[A] So the Agent Factory is blocked from **both** directions: a static
`runtime → agent` import violates Blueprint §21, and the dynamic discovery
Roadmap §7 prescribes violates the frozen no-reflection assertions. [A] This is
a genuine canonical tension between **Roadmap §7/§8** and the **Baseline 04B/04C
conformance discipline** — not a defect in either suite, and not something a
minimum correction resolves.

[D] **Reserved to the Founder.** Resolving it means deciding which instrument
governs the Runtime→Agent-Definition mechanism. I am not narrowing a suite to
admit reflection, and I am not adding a static edge canon prohibits.

## 10. Decision

[D] **`test_no_boundary_outside_agent_depends_on_agent` is NOT modified.**

Grounds: the standing invariant that a conformance test is never modified
merely to make an implementation pass; Blueprint §21; the Freeze's ratification
of an acyclic graph; and `DEC-P6-039` §13, whose required verification is what
produced this outcome.

[A] `DEC-P6-039` §13 is the reason this was caught. The Decision declined to
assume the assertion erroneous and demanded evidence first — and the evidence
reversed the premise. That is the second time in this arc an empirical
requirement has overturned an analysis I was confident in.
