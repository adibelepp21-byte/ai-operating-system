## Context

Canonical Domain Model invariant 2 requires every Agent Definition to implement at least one Capability. No equivalent minimum exists for Permitted Skills or Permitted Workflows. Agent Definition Framework §8 states explicitly that "the Domain Model states no minimum count for this field. Whether an empty set is a valid declaration is not settled by ratified text," and §15 tracks this as Open Architectural Question 5.

This gap is not a deliberate, documented deferral — unlike, for example, the Runtime entity-vs-attribute question, which §9 explicitly names as deferred pending future evidence. No comparable statement exists for Skill/Workflow cardinality anywhere in ratified text. The one real Agent Definition instance, the Governance Artifact Integrity Agent, currently declares zero Permitted Skills and zero Permitted Workflows, with its own document explicitly flagging both fields as resting on this unresolved question.

This ADR follows a completed Architecture Discovery Report (current-state analysis, dependency analysis, evidence review, full option enumeration), an Architecture Decision Analysis Report (option-by-option architectural evaluation), and an Architecture Decision Recommendation (independent re-review recommending Option A against the current governance system). These three documents are cited here as the analytical record behind this proposal; none of them carries governance authority in their own right — only this ADR, if approved, does.

## Decision

An Agent Definition may declare zero, one, or multiple Permitted Skills and zero, one, or multiple Permitted Workflows.

An empty Skill declaration, an empty Workflow declaration, or both empty declarations represent a valid architectural state.

This is grounded in three considerations from the analytical record, not invented here:

1. **Constitution §8** requires that complexity be added only when a demonstrated problem requires it. The only operational evidence available — the Governance Artifact Integrity Agent, functioning with zero Skills and zero Workflows, its authorization carried entirely by its independently-mandatory Behavior and Permissions field — shows this state working in practice, with no observed failure mode to justify a new constraint.
2. **Domain Model §2**'s own definition of Agent Definition groups Skills and Workflows together with behavior and permissions as things the entity "specifies," without singling them out for an invariant-backed minimum the way §7 invariant 2 explicitly singles out Capability. This drafting pattern treats Skills/Workflows descriptively, not prescriptively.
3. **The Domain Model and prior ADR history demonstrate that absence of related instances may be explicitly recognized as a valid state rather than automatically treated as non-compliance.** ADR-0003's treatment of a zero-Agent-Definition Capability as an explicitly expected, reviewable condition is supporting context for this reading, not a direct precedent for Skill/Workflow cardinality specifically — the two questions concern different relationships (Capability↔Agent Definition versus Agent Definition↔Skill/Workflow), and this ADR does not treat ADR-0003 as dispositive, only as consistent supporting context.

## Alternatives Considered

1. **Minimum one Skill (Option B).** *Rejected* — an unmotivated asymmetry privileging Skill over Workflow with no architectural basis found in the analytical record; would immediately break the only real Agent Definition instance's compliance, with no remediation path available since no Skill Framework exists; cuts against the Skill/Workflow structural symmetry ADR-0004 and ADR-0005 established.
2. **Minimum one Workflow (Option C).** *Rejected* — the same reasoning as Option B, compounded by an internal incoherence: Workflow is defined (§2) as a composition *of* Skills, so requiring a Workflow without requiring the Skills it composes is architecturally weaker than requiring a Skill alone.
3. **Minimum one Skill OR one Workflow (Option D).** *Rejected*, despite being architecturally competitive with the selected option in earlier analysis. Ultimately rejected because it would certainly and immediately break the Governance Artifact Integrity Agent's compliance, with no remediation path available under current governance, for a constraint the available evidence does not demonstrate is necessary under Constitution §8.
4. **Minimum one Skill AND one Workflow (Option E).** *Rejected* — the most speculative-forward option; would stall Agent Definition creation broadly until both Skill and Workflow Frameworks exist; no Domain Model precedent exists anywhere for a compound, two-entity-type minimum; least evidence-backed of all options considered.
5. **Context-dependent transitional minimum (Option F).** *Rejected* — while it would preserve backward compatibility, it introduces a new Domain Model invariant *style* (conditional/temporal invariants) with no precedent among the existing 14 invariants, a structurally larger change than the substantive question warrants, and requires precisely defining a "trigger" condition that was never attempted in the analytical record. Disproportionate to the problem being solved.
6. **Framework-level non-binding recommendation only (Option G).** *Rejected* — mischaracterizes the nature of the question. This is an invariant-shaped question reserved to the Domain Model under Constitution §6.2 invariant 3, not a documentation-convention question a Framework may resolve on its own authority. Would leave the actual question open indefinitely, in tension with the Governance Artifact Integrity Capability's own charter to resolve exactly this kind of unresolved inconsistency.

## Consequences

### Positive Consequences
- Preserves full compatibility with the Governance Artifact Integrity Agent — no remediation, exemption, or transition mechanism required.
- Adds no complexity beyond what current evidence demonstrates necessary, consistent with Constitution §8.
- Closes Agent Definition Framework Open Architectural Question 5 definitively.
- Provides a clear, citable Domain Model invariant that future Agent Definition authors and Frameworks can rely on, rather than the current unexplained silence.

### Negative Consequences
- Leaves open the possibility of an Agent Definition relying entirely on narrative Behavior-and-Permissions authorization with no Skill or Workflow backing — though this is independently bounded by that field's own requirement for substantive, real authorization, not created or expanded by this ADR.
- Does not resolve whether direct, non-Skill-mediated authorization is a sound *permanent* execution pathway for Agent Instances — an adjacent question this ADR deliberately does not address (see Non-Goals).

### Future Implications
- This decision is reversible through a future ADR if real operational evidence — once Skill/Workflow Frameworks and real Agent Instances exist — demonstrates an actual need for a minimum.
- Any future tightening ADR would need to address Agent Definitions that accumulated with zero Skills/Workflows under this decision; that migration cost is deferred to the point where real evidence would justify incurring it, not eliminated.

## Domain Model Impact

- **Entities affected:** Agent Definition (clarified, not redefined).
- **Relationships affected:** None — the "Agent Definition specifies Skill, Workflow" relationship (§4) is unchanged in content and is not altered by the invariant below.
- **Ownership impact:** Not applicable.
- **Lifecycle impact:** Not applicable — Agent Definition's §6 Lifecycle Rule is unchanged; this invariant introduces no lifecycle behavior.
- **Invariant impact:** Proposes one new invariant in §7:

  **Invariant 15 — Agent Definition Skill and Workflow Declaration**
  An Agent Definition may specify zero or more Skills and zero or more Workflows. An empty Skill declaration, an empty Workflow declaration, or both empty declarations represent a valid architectural state. No minimum cardinality is required for either relationship.

  This invariant does not modify invariant 2 (Capability's own "at least one" requirement, which remains untouched); does not alter any Agent Definition relationship in §4; introduces no lifecycle behavior into §6; and introduces no Framework-level authority — it is a Domain Model semantic statement only, per Constitution §6.2 invariant 3, and ADR-0007 is the sole artifact introducing it.

## Non-Goals

This ADR does not:
- Resolve whether direct, non-Skill-mediated Behavior-and-Permissions authorization is a permanent, architecturally sound Agent Instance execution pathway.
- Resolve Framework sequencing (which of Skill, Workflow, Runtime, or Tool Frameworks is built first).
- Define validation authority or timing for any future minimum, should one ever be adopted.
- Alter Capability's own minimum requirement (invariant 2).
- Create a Skill Framework, a Workflow Framework, or any other Framework.
- Modify the Governance Artifact Integrity Agent document.
- Redefine Agent Definition, Skill, Workflow, or any other Canonical Domain Model entity, relationship, ownership rule, or lifecycle rule.
