# ADR-0012

## Metadata

- **Identifier:** ADR-0012
- **Title:** Establish `docs/architecture/volume-2/` as the canonical repository
  namespace for Volume 2, and relocate the PD-02 Architecture Office corpus into it
- **Status:** **Approved**
- **Decision Owner:** Architect (Founder)
- **Proposer:** Claude Code / Co-Founder (Construction Phase)
- **Approval Record:** Executed under the Founder's Post-Phase-D Remediation

---

## Context

The PD-02 corpus was made repository-resident under `ACT-CC-F03-010` at
`docs/architecture/volume-1/pd-02-architecture-office/`, following the naming
convention established by `docs/architecture/volume-1/pd-01-executive-office/`.

`ACT-CC-F03-011` (Phase D) found this creates a repository identity conflict:
**all 50 resident bodies declare `Volume: Volume 2`, while the containing
directory declares volume-1.** The directive required this to be resolved by
evidence, not aesthetics, and explicitly forbade silent correction.

---

## Problem Statement

Is `volume-1/` a **volume namespace** (in which case Volume 2 content inside it
is an identity error), or merely a **legacy container** whose name is tolerated?

The question was decided from resident evidence, under the directive's order of
authority — which excludes conversational designation from counting as authority.

---

## Evidence

| Test | Result | Reads as |
|---|---|---|
| PD-02 bodies declaring `Volume: Volume 2` | **50 / 50** | Volume 2 |
| PD-02 bodies declaring Volume 1 | **0 / 50** | — |
| PD-01 bodies declaring Volume 2 | **0 / 45** | — |
| `docs/architecture/volume-2/` existed | **NO** | — |
| What `volume-1/` contained | PD-01 **and** PD-02 | two different volumes |
| Resident governance artifacts designating the PD-02 path | **0** | no authority for the old path |
| Resident references to `pd-02-architecture-office` outside the corpus | **0** | relocation breaks nothing |
| Every resident `volume-1` reference (7 artifacts) | denotes **Volume 1 / PD-01** content | `volume-1` is a volume assertion |

Every resident use of `volume-1` in the repository denotes Volume 1 content.
The directory name is therefore a **volume assertion**, not a neutral container —
so Volume 2 content inside it is an identity error, not a tolerable legacy name.

This is **Option B** under the directive's §6.

---

## Decision

**`docs/architecture/volume-2/` is the canonical repository namespace for
Volume 2.**

The PD-02 Architecture Office corpus is relocated to
`docs/architecture/volume-2/pd-02-architecture-office/`, preserving the
`<Section>.md` naming convention established by PD-01. Volume namespaces and
platform-division sub-namespaces both remain as they were; only the volume
namespace is corrected.

---

## Scope

- Move `docs/architecture/volume-1/pd-02-architecture-office/` →
  `docs/architecture/volume-2/pd-02-architecture-office/` (51 files).
- Record the canonical path in the residency manifest.

**Content-preserving.** The move is a relocation of repository identity, not a
change of source semantics. No body was opened, rewritten, reformatted, or
re-extracted.

---

## Non-Scope

- **The 50 body files' contents** — byte-identical to Founder-supplied source and
  never rewritten for any reason, including relocation.
- **Volume 1 / PD-01** — untouched; `volume-1/` now contains exactly what its
  name asserts.
- Historical evidence, ADR-0001 … ADR-0011, the Engineering Constitution, the
  Architecture Freeze, the Finding Register, `native_core/`.
- No new naming convention is invented: `volume-N/platform-division/` is the
  existing convention, applied correctly.

## Consequences

**Positive.** Repository path and corpus metadata agree. `volume-1/` again
contains only Volume 1. A future reader cannot mistake PD-02 for Volume 1
content. Git history follows the files through the rename.

**Accepted cost.** Paths recorded in conversational reports predating this ADR
refer to the old location. Those are historical records and are not rewritten;
this ADR is the bridge.
