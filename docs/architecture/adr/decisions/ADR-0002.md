# ADR-0002

## Metadata

- **Identifier:** ADR-0002
- **Title:** Correct stale future-tense Constitution-formalization reference in Domain Model §11
- **Status:** Approved
- **Proposer:** AI Systems Engineer
- **Approval Record:** Approved by Architect — see Approval Record
  section, below.

## Context

The Canonical Domain Model v1.0's Version Declaration (§11) was written
before the Engineering Constitution existed, and describes the Domain
Model's relationship to the Constitution in future tense. The Engineering
Constitution has since been ratified and, per Constitution §5 (Semantic
Foundation Clause), has already formalized the Canonical Domain Model's
role as AIOS's semantic foundation. The stale future-tense wording no
longer matches current governance reality.

ADR-0001 established the precedent that corrections to the Canonical
Domain Model — regardless of how administrative — require an ADR under
Constitution §5, because no other mechanism may alter that document. This
ADR follows that same precedent for a second, unrelated instance of the
same staleness pattern, found in a different section of the same
document.

## Problem Statement

§11's "Serves as" bullet states that the Engineering Constitution "will
formalize" the Domain Model into governance language — describing a
completed action as though it were still future. No semantic model
content is affected by this inconsistency; it is confined to the Domain
Model's own description of its relationship to the Constitution.

## Decision

Replace, in Canonical Domain Model §11 (Version Declaration), the "Serves
as" bullet's wording:

> "the semantic foundation the Engineering Constitution will formalize
> into governance language"

With:

> "the semantic foundation the Engineering Constitution has formalized
> into governance language"

No other content in §11, or elsewhere in the Canonical Domain Model,
changes.

**Explicit confirmation of scope:**
- **Zero entities affected.** §1 (Canonical Entity List) and §2 (Entity
  Definitions) are untouched.
- **Zero relationships affected.** §4 (Relationships) is untouched.
- **Zero ownership rules affected.** §5 (Ownership Rules) is untouched.
- **Zero lifecycle rules affected.** §6 (Lifecycle Rules) is untouched.
- **Zero invariants affected.** All 14 invariants in §7 are untouched.

## Alternatives Considered

1. **Leave wording unchanged.** Rejected — the Constitution now exists
   and has already done what the sentence describes as still future;
   leaving it diverges from what the document describes.
2. **Direct edit without an ADR.** Rejected — precluded by Constitution
   §5, which permits no mechanism other than an approved ADR to alter the
   Canonical Domain Model, per the precedent already established by
   ADR-0001.
3. **Modify the Constitution instead.** Rejected — the stale text lives
   in the Domain Model, not the Constitution; Constitution §5 already
   describes this relationship accurately in present tense. Editing the
   Constitution would target the wrong document and would invoke the
   heavier Constitutional Amendment process for no benefit.
4. **Bundle unrelated documentation corrections** (for example, the
   remaining "(planned)" labels in the root `README.md`). Rejected —
   those corrections do not require an ADR at all and should not be
   coupled to one that does; keeping this ADR narrow continues the
   precedent ADR-0001 set.

## Consequences

Canonical Domain Model §11 becomes accurate and consistent with the
ratified Constitution. No semantic structure changes — no entity,
relationship, ownership rule, lifecycle rule, or invariant is affected.
This ADR also exercises the ADR mechanism a second time, consistently
with the pattern ADR-0001 established for narrow, single-clause
corrections to the Canonical Domain Model.
