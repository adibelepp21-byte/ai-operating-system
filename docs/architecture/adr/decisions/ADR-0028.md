## 1. Result

E-01 exists. `consumers/ReferenceAgent` is a concrete `Agent`, participates
against a running Runtime, and completes — **without one line of
`native_core/` changing and without one conformance assertion moving.**

## 2. The region

**Name: `consumers/`.** [A] Chosen over `applications/`, `products/` and
`agents/` because canon already names these *"future, separately authorized
**consumer phases**"* (`agent.py`, `consumer.py:35,:75`,
`execution/contract.py`), and every resident realizes a Native Core contract —
today `ExecutionConsumer`. [A] The name also does enforcement work: it states
the admission rule, so *"implements no core contract"* is a sufficient reason to
refuse a module. `applications/` would have invited the general holding area
`ACT-CC-P6-055` §7 warns against.

| | |
|---|---|
| **Owns** | concrete implementations of Native Core contracts |
| **Excludes** | anything belonging to the core · tooling, validators, catalog readers (`tools/`) · documentation (`docs/`) · anything with no core contract to implement |
| **Structure** | a real package with `__init__.py`, matching `native_core/`; `tools/` is a namespace directory and was not the model |
| **Layout** | flat — one resident, no by-boundary grouping built for hypothetical future ones |

[A] **Why not `native_core/`:** the agent boundary is a *contract* boundary and
its suite enforces that — one cross-boundary import, no Execution names, no
Runtime identifiers, no new raise site. A meaningful consumer cannot satisfy all
four (`ACT-CC-P6-039`). [A] **Why not `tools/`:** `tools/` is repository tooling
— validators, the catalog reader, the composition root. A product consumer there
would be a category error, and `DEC-P6-042` forecloses it explicitly.

## 3. Dependency direction — the reason the region exists

```
consumers/    ──depends on──▶   native_core (public contracts)
native_core/  ──never───────▶   consumers/
```

[E] Measured across all three code regions:

```
native_core -> []                consumers -> ['native_core']
tools       -> ['native_core']   REGION CYCLES: NONE
native_core -> consumers : False
```

[A] The core must never learn a consumer exists. Residency here is what makes
that true **structurally** rather than by convention — and it is why no core
assertion had to move. [E] Pinned by `test_the_native_core_imports_nothing_from_consumers`
and by a fresh-interpreter check that importing the core loads no `consumers`
module.

## 4. E-01 — what it does, and what it refuses to do

`consumers/reference_agent.py` · `ReferenceAgent(Agent)`.

[A] It **completes**: `participate` returns `None`, and per
`agent_execution_semantics_spec` §13.3 that return *is* the completion signal —
completion is defined negatively, as the absence of rejection and failure, since
no result model is ratified.

[A] Three things it deliberately does **not** do, each because the spec forbids
it, not because it was easier:

1. **No rejection.** §4: *"Rejection is not the consumer's decision to make
   about its own admission."* Both realized conditions are enforced at the
   Runtime/Execution boundary before a consumer is reached.
2. **No precondition check.** §17.2: *"Specifying preconditions does not
   authorize adding a precondition check."* §13.2's four are enforced upstream
   and structurally.
3. **No manufactured failure.** §5 places failure under `ExecutionError` and
   adds no base. This consumer has no work that can fail, so it declares no
   failure condition it does not have — inventing one to look substantial is
   exactly the implementation-by-implication §17.2 bars.

[E] `participated_sequences` is in-memory evidence, **not a Trace**. Trace is
authored by the Runtime under INV-4 and is the only durable record (§16).

[A] **What residency actually bought:** `execution.context.execution_sequence`.
Inside the core boundary, C3 forbids naming the hosting Runtime at all, so an
Execution could be *received* but never *read*. That single line is the
difference between `ACT-CC-P6-039`'s option iii — a vacuous consumer — and a
real one.

constraints anyway sets the better precedent.

[E] **Disclosure — a recurring defect in my verification code, third
occurrence.** I asserted `assertNotIn("ExecutionSession", source)`; the module's
docstring names those types precisely to explain that it does not import them,
so the substring reported that explanation as a violation. Rewritten to check
imported **names by AST**, which is what it claimed to test. The same substring-
for-syntax error is disclosed in `ADR-0024` §5. [A] It has now recurred often
enough to be a pattern worth naming rather than a slip worth noting: when a test
asserts an *import* property, it must read imports, never text.

## 7. Rejected alternatives

| Alternative | Why rejected |
|---|---|
| `applications/` · `products/` | Broader than the admission rule; invites the general holding area §7 warns against |
| `agents/` | Names one contract; the region admits any core-contract realization |
| Namespace directory (no `__init__.py`), as `tools/` | The region has a declared public surface; `native_core/` is the right model |
| By-boundary subpackages | Organization built for hypothetical residents |
| E-01 raising to demonstrate failure | Manufactures a failure condition it does not have (§17.2) |
| E-01 validating its own admission | §4 — rejection is not the consumer's decision |

## 9. Findings

1. **[E]** `DEC-P6-042` has no persisted record; its text is inline in the
   issuing Act. It is the ninth in the pattern recorded by
   `ACT-CC-P6-056` — unaffected by that Act's open recovery gate, since the
   authorization was issued directly here rather than only cited.
2. **[E]** The issuing Act was numbered `ACT-CC-P6-055`, an identifier already
   consumed (E-01 Consumer Phase Authorization Gate → `ADR-0027`); by sequence
   this is `ACT-CC-P6-057`. Executed on content, not number.
3. **[A]** The region currently holds one resident. If it acquires several,
   revisit the flat layout — but not before.
4. **[R]** `consumers/` has no conformance suite of its own. None is required
   today: 22 evidence tests pin its boundary, dependency direction and
   admission rule. If the region grows, a suite becomes worth having.
