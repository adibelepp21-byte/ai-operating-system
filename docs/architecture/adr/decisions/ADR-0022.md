# ADR-0022

## Metadata

- **Identifier:** ADR-0022
- **Title:** Runtime catalog population is **Architect-reserved and non-code** —
  and the canonical entry records its hosted relationship **"by reference only"**
- **Status:** **PARTIAL** — ownership, partition, representation and persistence
  path established; **construction BLOCKED**
- **Decision Owner:** Founder (**ACT-CC-P6-049**) · **Executor:** Co-Founder
- **Approval Record:** Executed under `ACT-CC-P6-049` §25. Discovery completed;
  §20 stop conditions **1** and **3** reached. Nothing was constructed.

---

## 1. Result

`ACT-CC-P6-049` asked who authors governed host declarations, into which
partition, through what persistence path. **All three are answered — and none of
the answers is code.** A code-side population mechanism is therefore not merely
unauthorized; it would **displace an authoring path canon assigns to the
Architect**.

A second, independent blocker was found beneath the first: **the canonical
catalog entry does not carry a machine-readable host declaration at all.**

## 2. Evidence

### E-01 — Ownership: the Architect, by documentation change

[E] **EARC §3:** *"Ownership of this repository convention **does not grant
modification authority, access authority, or operational permission** over any
repository artifact. Repository access and permissions are governed **separately
from**, and are not affected by, this document's content."*

[E] **EARC §11** — *"This document does not, and may never: … **Grant
modification authority, access authority, or operational permission over any
repository artifact.**"*

[E] EARC is the **only** canonical instrument governing the execution catalog,
and it disclaims the authority twice, deferring it to something it does not name.

[E] **Runtime Framework §9:** *"**Owning designation** — Runtime is owned
centrally (Domain Model §5) … **it does not name an owning Department, since
none exists for this entity.**"* Central ownership is a *status*, not a named
authority.

[E] The mechanism canon does record, repeatedly, for every change to these
documents: *"separate, **direct Architect-approved documentation changes**"*
(Runtime Framework §41, §93; EARC §3).

[A] **Catalog population is an Architect-approved documentation change.** No
party other than the Architect is designated, and no code path is contemplated.

### E-02 — Partition: RESOLVED (Act §9 **Outcome A**)

[E] **EARC §10, Open Question 1 — "Repository organization specifics —
CLOSED."** The directory name (`execution-catalog`), **the complete repository
path (`docs/architecture/organization/execution-catalog/`)**, the canonical
identifier model, the canonical key format, the reference model, and the
internal organization model (`skill/`, `workflow/`, `runtime/`, `tool/`) *"have
all been resolved."* [E] EARC §9 *"Not Yet Defined"* confirms: *"No unresolved
item remains."*

[A] The canonical partition is **`docs/architecture/organization/execution-catalog/runtime/`**, and it is **already populated** — three governed entries.

### E-03 — Representation: a governed markdown document

[E] `tools/validators/catalog.py` — canonical key `runtime.<slug>` matching
`^(skill|workflow|runtime|tool)\.[a-z0-9]+(-[a-z0-9]+)*$`, with
`REQUIRED_HEADERS["runtime"] = ["## Metadata", "## Purpose / Description",
"## Hosted Relationship", "## Compatibility Boundary Representation",
"## Version History"]`.

[A] **This is not a stored-record representation.** It is a ratified document
structure. The decoding seam built in `ADR-0021` decodes JSON records from a
`StorageFacility` partition — correct and generic for stored records, but the
canonical Runtime catalog is **not** stored records. `ADR-0021` Finding 3
flagged exactly this as open; discovery has now resolved it, and the answer is
that the two representations differ.

### E-04 — Persistence: the repository itself

[A] The persistence path is the governed repository, through documentation
change and review — not `StorageFacility.append`. [E] Every tool touching the
catalog **validates**: `tools/validate_execution_catalog.py`,
`tools/validators/catalog.py`, `…/agent_integration.py`. [E] A repository-wide
search for a catalog **writer** returns none. Reading and validating is the
entire established pattern.

### E-05 — Authority: population carries none, and would usurp one

[A] Expected answer confirmed, and then sharpened: population does not merely
*lack* governance authority — building it in code would **create authority canon
assigns elsewhere**, which `ACT-CC-P6-049` §6 forbids in terms. **§20 stop
condition 3.**

### E-06 — End-to-end: proven, but only heuristically

[E] Measured in memory against the **real** catalog:

```
runtime.batch-governance-review-substrate         -> ('Governance Artifact Integrity Agent',)
runtime.interactive-governance-session-substrate  -> ('Governance Artifact Integrity Agent',)
runtime.textual-reasoning-execution-substrate     -> ('Governance Artifact Integrity Agent',)

resolve('Governance Artifact Integrity Agent') -> runtime.batch-governance-review-substrate
```

[A] The governed catalog **is** compatible with the `DefinitionCatalog` built in
`ADR-0020`: it resolves deterministically, fails closed, and loads no agent
module. The frontier is one reader away.

[I] **But the extraction was a heuristic I invented** — a markdown-link regex
over the `## Hosted Relationship` prose. It is **not canonical**, and it is
disclosed as inference, not evidence. This measurement was in-memory only;
nothing was persisted.

## 3. The deeper blocker — "by reference only"

[E] **Runtime Framework §9, Mandatory Document Fields:**

> **"Hosts Agent Instance"** — a **documentation field** recording, **by
> reference only**, that this Runtime may host Agent Instance execution, per
> Domain Model §4's Runtime-hosts-Agent-Instance relationship. This field
> **records the existence of this relationship**; it does not define, redefine,
> or describe Agent Instance's own behavior, lifecycle, or execution semantics.

[E] `tools/validators/catalog.py` requires only that the **header**
`## Hosted Relationship` be present. **No validator checks a declaration
payload, and no ratified rule defines one.**

[A] So the canonical entry records **that** a hosting relationship exists — not,
in any machine-readable form, **which** Agent Definitions may be hosted. The
field was designed to be *cited*, not *consumed*. Any reader must therefore
invent representation semantics, which `ACT-CC-P6-049` §3.13, §6 and §10 each
forbid.

[E] Reinforcing this: **EARC §11** holds that *"slug normalization rules and
filename conventions for canonical keys … **remain open, deferred to a separate,
later instance-convention decision**."*

## 4. Decision required — [D] Founder / Architect

> **Does a Runtime catalog entry carry a machine-readable declaration of which
> Agent Definitions it may host — and if so, in what ratified field?**

Until that is decided, no reader can consume the catalog without inventing
representation, and no writer may exist without displacing the Architect's
authoring path.

[A] Subordinate to it, and only if the answer is yes: whether a reader belongs
in `tools/` (where every other catalog consumer lives) or elsewhere. **Not
decided here** — `ACT-CC-P6-049` §3.8 restricts composition-root creation, and
the question is moot until the representation exists.

## 5. Alternatives rejected

| Alternative | Why rejected |
|---|---|
| Build a catalog **writer** persisting declarations to a `StorageFacility` | §20.3 — usurps the Architect's authoring path; EARC §3/§11 disclaim the authority twice |
| Build a **reader** over the current markdown | Requires inventing the machine-readable form of a field canon defines *"by reference only"* (§3) |
| Treat my link-extraction regex as the representation | It is inference, not canon. Recorded as `[I]`, never promoted |
| Add a machine-readable field to the catalog documents | Modifies ratified governance documents; Architect-reserved |
| Redefine the catalog as a `StorageFacility` partition | Contradicts EARC §10's **CLOSED** repository path (E-02) |
| Populate a partition of my own | §9 **Outcome D** guard — *"Do not invent a partition merely to complete the Act"* |

## 7. Findings

1. **[E] `GOVERNANCE_INDEX.md` §6 contradicts EARC.** The Index lists as *open*
   two items EARC records as **resolved/CLOSED**: *"Complete repository path
   beyond the `execution-catalog` directory name"* and *"Literal canonical-key
   format."* The Index was last updated **2026-08-08**; EARC **2026-07-18** — so
   the Index is the **newer** document and the divergence is not an ordering
   artifact.
2. **[E] `GOVERNANCE_INDEX.md` §3 states *"no instance currently exists"*** for
   Skill/Workflow/Runtime/Tool. Three Runtime instances were added **2026-07-31**
   (`a8c1fbb`), eight days before the Index's last update.
3. [A] Both are **reported, not corrected.** `ACT-CC-P6-049` §5 permits reporting
   only, and governance documents are amended by direct Architect-approved
   change — the very mechanism this ADR identifies (E-01). Correcting them here
   would enact the authority the Act just established I do not hold.
4. **[A] `ADR-0021`'s decoding seam remains correct and generic** for stored
   records. It is simply not yet connected to anything, because the canonical
   catalog is not a stored-record representation. No rework is implied.
