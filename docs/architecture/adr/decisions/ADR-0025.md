# ADR-0025

## Metadata

  neither half may see the other
- **Status:** **Approved** · `ACT-CC-P6-053` **COMPLETE**
- **Decision Owner:** Founder (`ACT-CC-P6-053`) · **Executor:** Co-Founder

## 1. Problem

`ADR-0024` left the supported path assembled by hand: a caller had to know both
`tools.runtime_catalog.host_declarations()` and
`DefinitionCatalog.from_records()`, and wire them itself. `ACT-CC-P6-053` asked
for the smallest coherent supported path.

## 2. Placement is forced, not chosen — [E]

[E] Two constraints, each independently established and each pinned by a test:

| Constraint | Source |
|---|---|
| `tools.runtime_catalog` imports **nothing** from `native_core` | `ADR-0024` §4 · `test_the_reader_imports_nothing_from_the_native_core` |
| `native_core` imports **nothing** from `tools` | the core must not depend on repository layout; the Runtime stdlib allowlist admits no parsing module (`ADR-0021` §2) |

[A] **Neither half can compose the path, because each is deliberately blind to
the other.** Something above both must. That determines placement before any
preference does — `tools/runtime_composition.py`, importing both.

[A] This is the caller `agent/definition.py` describes **twice** as *"a caller
that can see both sides"*, and which `ACT-CC-P6-041` found had never been built.
That thread is now closed.

## 3. Pattern — [E] the repository's own

[E] Four boundaries already establish the idiom: `runtime/composition.py`,
`runtime/execution/composition.py`, `knowledge/composition.py`,
`optimization/composition.py` — each a module exposing a single `create_*`
factory that assembles collaborators and constructs nothing else.

[A] Followed exactly:

```python
create_definition_catalog(runtime_dir=None) -> DefinitionCatalog
resolve_host(definition_name, selector=None, runtime_dir=None) -> HostDeclaration
```

[E] `test_the_composition_adds_no_behaviour_of_its_own` pins it: no classes, and
exactly those two functions. [E] `test_no_module_level_mutable_state_exists`
pins the absence of state.

## 4. Decisions made under delegation — [A]

1. **`tools/`, not `native_core/`** — forced by §2.
2. **Two functions, not one.** `resolve_host` is the one-call path;
   `create_definition_catalog` is kept separate because a caller resolving
   several names should build the catalog once rather than re-read the catalog
   per name.
3. **No caching, no memoisation.** Each call reads fresh, so a catalog edited
   between calls is *observed, never remembered*
   (`test_a_changed_catalog_is_observed_not_remembered`). A cache would be
   hidden state, which `ACT-CC-P6-053` §10.7 bars.
4. **Error families are deliberately not collapsed.** A representation failure
   raises `CatalogReadError` (reader); a meaning failure raises
   `MalformedDeclaration` / `UndeclaredDefinition` / `UnknownHost` (Runtime).
   [A] Which layer refused is diagnostic, and flattening it would erase the
   ownership split `ADR-0021` established. Pinned by
   `test_the_two_error_families_are_not_collapsed`.
5. **No public-surface expansion in `native_core`.** `AIOSRuntime`'s public
   surface, `Runtime.__abstractmethods__` and `runtime.__all__` are all pinned
   by equality and remain untouched; `F-4` is not resolved or approached.

## 5. Rejected alternatives

| Alternative | Why rejected |
|---|---|
| Compose inside `native_core` | Would require importing `tools`, coupling the core to `docs/` layout; `re` is outside the Runtime stdlib allowlist |
| Compose inside `tools/runtime_catalog.py` | Would break its `native_core`-free property, which `ADR-0024` pinned deliberately |
| A method on `AIOSRuntime` | Public surface pinned by equality; and hosting composition is not the realization's work |
| A stateful `HostResolver` object holding a cached catalog | Hidden state (§10.7); the cache buys nothing at this scale and hides catalog edits |
| One function only | Forces a re-read per name resolved |
| A single flattened error type | Erases which layer refused |

## 7. Findings

1. **[A]** The composition is intentionally thin — assembly with no behaviour.
   If hosting ever needs policy (selection among several declaring hosts beyond
   deterministic first-in-key-order), that is new behaviour and belongs in a
   decision, not smuggled into a composition root.
2. **[D] Architect-reserved, unchanged and not approached:** the authority
   classification of the hosting reference (descriptive · advisory ·
   authoritative). This Act composes *reading*; assembling a path confers no
   authority on what flows through it.
3. **[A]** `tools/` now holds three cooperating modules — `runtime_catalog`
   (representation), `runtime_composition` (assembly), and the validators. The
   split matches `ADR-0021`'s: representation in tooling, meaning in the core.
