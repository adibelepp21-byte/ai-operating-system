# ADR-0021

## Metadata

- **Identifier:** ADR-0021
- **Title:** Stored-record decoding belongs to **Infrastructure** — the boundary
  that writes the bytes reads them back
- **Status:** **Approved** · Act **COMPLETE**
- **Decision Owner:** Founder (**ACT-CC-P6-048**) · **Executor:** Co-Founder
- **Approval Record:** Executed under `ACT-CC-P6-048` §3/§8/§11.

## 1. Problem

`ADR-0020` Finding 2: `StorageFacility.read()` yields `Iterator[bytes]`, and
`DefinitionCatalog.from_records` consumes `Iterable[Mapping]`. Nothing owned the
step between them. Runtime could not own it — its conformance allowlist admits
no serialization module — so the seam had no canonical home.

## 2. Provenance — what the Runtime allowlist actually is

[E] The assertion that rejected `json` is `test_no_external_dependency_exists`,
whose docstring reads *"INV-12: Tool is the only entity permitted an external
dependency."* Its implementation checks membership in:

```python
STDLIB = frozenset({"__future__", "dataclasses", "types", "abc", "typing", "enum"})
```

[E] The stdlib modules the Runtime boundary imported at Baseline 04B:
`__future__`, `dataclasses`, `types`, `abc`, `typing`, `enum` — **the set is an
enumeration of exactly what the boundary happened to import.** Introduced by
`9731964` (2026-08-06), the verification-only baseline that also produced the
ungoverned narrowing corrected in `ADR-0016`.

[E] Every other boundary implements INV-12 differently:

| Boundary | Mechanism |
|---|---|
| Trace, Infrastructure | **denylist** of third-party packages (`requests`, `torch`, `sqlalchemy`, …) |
| Knowledge | `sys.stdlib_module_names` — the whole standard library |
| Runtime | six-module **allowlist** |

[A] INV-12's canonical subject is **external** dependency. `json` is standard
library, so INV-12 does not reach it; only the enumerated allowlist does,
incidentally. [E] Trace decodes its own records with `json` today
(`trace/reader.py`) under the denylist and is conformant.

[A] **I did not change the allowlist.** `ACT-CC-P6-048` §5 forbids weakening an
assertion to make an implementation pass, and §6.4 permits treating an assertion
as a change candidate only where delegated authority explicitly says so — it
does not. The narrowness is **reported as a finding, not acted on**, and the
design was moved instead. That the resulting architecture is better than the one
the assertion rejected is the substantive point, not a consolation.

## 3. Decision

**Decoding belongs to Infrastructure.** `native_core/core/infrastructure/records.py`:

```
decode_record(raw) · decode_records(raws) · read_records(storage, partition)
                                          · RecordDecodeError
```

[A] Grounds — three, independent of the allowlist:

1. **Symmetry of ownership.** Infrastructure writes the bytes
   (`LocalAppendOnlyStorage.append`). The boundary that chose the stored
   representation is the one that can read it back. Decoding is the inverse of
   a responsibility Infrastructure already holds.
2. **Blueprint §14** places facilities *beneath* entities so an entity boundary
   is never obliged to know how its data was written down. A Runtime that
   decoded bytes would know exactly that.
3. **INV-12 is satisfied natively here** — Infrastructure is the boundary whose
   conformance already governs storage-shaped concerns, and it holds nothing
   external.

## 4. The seam: representation, not meaning

```
stored bytes ─→ Infrastructure decoding ─→ Runtime DefinitionCatalog ─→ host
               "what did the store hold?"    "what does it mean?"
```

[A] The decoder validates that a record is a well-formed JSON **object** and
nothing further — no schema, no field vocabulary, no domain type, no entity.
`DefinitionCatalog.from_records` applies every Definition rule itself. [E]
`test_the_decoder_imposes_no_vocabulary_the_catalog_enforces_it` pins the split:
`{"unrelated": "field"}` **decodes successfully** and is **rejected by the
catalog**. Neither side can be quietly relocated into the other without that
test failing.

[E] **Runtime required no change.** `from_records` was already the seam;
`ACT-CC-P6-047` built the correct joint before this Act knew where the other
half belonged.

## 5. Alternatives rejected

| Alternative | Why rejected |
|---|---|
| Widen the Runtime `STDLIB` allowlist to admit `json` | §5 / §6.4 — weakening an assertion to pass an implementation. Also worse: it puts representation knowledge in an entity boundary |
| A decoding **`Facility`** | A decoder holds no resource, opens nothing, has no lifecycle. `Facility` grants `provision`/`release`/readiness a pure function cannot meaningfully be in |
| Decoding inside `StorageFacility` | Storage is append-only bytes by contract; adding format knowledge would give one facility two responsibilities and bind every consumer to JSON |
| Per-boundary decoding (the Trace pattern) | Trace decodes *its own* records under a denylist; Runtime cannot, and duplicating a decoder per consuming boundary multiplies the format decision |
| A composition root outside `core` | The gap is inside the core; exporting it would leave the seam unowned and untested |
| Schema validation in the decoder | Would move Definition vocabulary into Infrastructure and break the ownership split in §4 |

## 6. Dependency consequences — none

[E] Whole-core AST sweep, unchanged from before the Act:

```
agent -> ['runtime']            infrastructure -> ['shared']
runtime -> ['infrastructure', 'knowledge', …]
CYCLES: NONE          runtime -> agent: False
```

[A] `records.py` imports `json` (stdlib) and `.storage` (same boundary). **No
new cross-boundary edge exists anywhere in the core.** The acyclic graph is
untouched, and `test_the_whole_path_loads_no_agent_module` proves the full
stored-bytes-to-host path loads no agent module in a fresh interpreter.

## 8. Findings

1. **[E] The Runtime `STDLIB` allowlist is an enumeration, not a policy** (§2).
   It cites INV-12, which concerns *external* dependency, but excludes the
   standard library wholesale. Three other boundaries implement INV-12
   correctly and differently. **Reported, not acted on.** [D] Whether Baseline
   04B's allowlist should become a denylist is **Founder-reserved** — it is the
   same class of narrowing as `ADR-0016`, from the same commit, and must not be
   corrected as a side effect of construction.
2. **[A] The seam is decode-only.** Nothing here encodes. Authoring governed
   catalog data is a governance concern this Act did not touch, so no writer
   was built; tests encode with `json` directly. If a governed writer is ever
   authorized, symmetry should be revisited deliberately.
3. **[A] No governed catalog partition is populated.** The capability reads
   whatever a store holds; *which* store, and who writes the declarations, is
   an open composition question — not a defect in the seam.
4. **[D] F-4 export drift** — untouched, per §10. `DefinitionCatalog` remains
   unexported; the four decoding names are exported because Infrastructure's
   surface carries no equivalent recorded finding and no pinned inventory.
