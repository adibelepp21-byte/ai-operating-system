## 2. The scope finding — [E]

[E] Every one of C1–C4 is evaluated over `native_core/core/agent/`. [E] The
companion reverse-edge assertion resolves `CORE = native_core/core` and iterates
`CORE.rglob("*.py")`:

```python
for path in sorted(CORE.rglob("*.py")):
    relative = path.relative_to(CORE).parts
    if "tests" in relative or (relative and relative[0] == BOUNDARY):
        continue
```

[A] **A module outside `native_core/core/` is reached by none of them.** This is
the same structural fact that made `tools/runtime_composition.py` legitimate
(`ADR-0025`): these assertions govern the core, and they govern it exactly.

## 3. Empirical proof — [E]

An ephemeral consumer defined **outside the core**, driven against a real
Runtime:

```
runtime state: RuntimeState.RUNNING
execution: ExecutionSession | runtime_id: probe-runtime | seq: 0
PARTICIPATED. sequences seen: [0, 1]
FAIL-CLOSED -> an execution is required
isinstance(Agent): True
```

[E] That consumer **raised** — which C4 forbids inside the boundary — and
**reached `execution.context`** — which C3 forbids inside the boundary — while
receiving genuine `ExecutionSession` objects with an incrementing sequence, and
remaining a true `Agent`. [E] No reflection, no dynamic import, no new edge:
`runtime → agent` **False**, **CYCLES: NONE**, all suites green.

## 4. Explicit correction — [D] withdrawn, per §2.12

`ACT-CC-P6-039` recorded:

> *"**A meaningful E-01 has nowhere canonical to live.** That is the blocker,
> and it is structural rather than a matter of effort or sequencing."*

[A] **That claim is withdrawn as a general blocker.** Its §4 table enumerated
five candidate locations — a new module in the agent boundary, inside
`agent.py`, an agent subpackage, `runtime/execution/`, and a new top-level core
boundary. **Every candidate was inside `native_core/core/`.** Whether E-01 must
live in the core was never tested, and §3 shows it need not.

[A] What `ACT-CC-P6-039` measured was correct and remains correct: *within the
Native Core*, a meaningful `participate()` has nowhere to live. The error was
the unstated premise that the core was the only place to look — the same class
of scope error corrected in `ADR-0024`, where I searched canon for a field and
never searched the tooling that already read it.

[A] And its §3 — *"This is correct architecture, not a defect"* — is **confirmed,
not overturned.** Three modules say implementations belong to *"future,
separately authorized consumer phases."* C1–C4 are the mechanism that **keeps
implementations out of a contract boundary**. They were never obstacles to route
around; they are a wall with a door, and the door is outside the core.

## 5. What remains — [D] the allocation gate

[E] The repository has exactly three top-level regions: `docs/`, `native_core/`,
`tools/`. **No application region exists.**

[A] `tools/` is repository tooling — validators, the catalog reader, the
composition root. A production Agent implementation is not tooling, and placing
one there would be choosing a region by convenience rather than architecture
(`ACT-CC-P6-054` §2.6).

[E] `consumer.py:35, :75` — implementations come from *"future, **separately
authorized** consumer phases"*, and the declaration *"carries no"* authority of
its own.

[D] **Two halves of one narrow question, neither delegated:**

> **Where does an authorized consumer-phase implementation reside — and is the
> consumer phase authorized to begin?**

[A] Why engineering cannot decide it: creating a fourth top-level region is a
repository-structure allocation, not an implementation detail; and the phase
authorization is stated as reserved in three canonical modules. `DEC-P6-034`
authorized E-01's *construction*, but `ACT-CC-P6-039` returned a blocker against
it, so whether that authorization is still live is itself a question I decline to
assume.

## 6. Options — [R] recommendation only

| Option | Effect |
|---|---|
| **A** — authorize a fourth region for consumer-phase implementations | E-01 becomes constructible immediately; the core stays untouched; the region is outside Blueprint §4's core-scoped eleven |
| **B** — place consumer implementations under `tools/` | Available today with no decision, but conflates tooling with product |
| **C** — leave E-01 unbuilt | Costs nothing; the contract boundary is complete and correct as it stands |

[R] **A**, if E-01 is still wanted. [R] **C** is entirely respectable: nothing
downstream currently needs a concrete consumer, and `ACT-CC-P6-039`'s judgement
that the reservation is *correct architecture* argues for leaving it reserved
until something real consumes it.

[A] I record these as options, not a selection. Choosing among them is the gate.
