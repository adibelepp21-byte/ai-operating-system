# 1. Purpose

E6 menetapkan bagaimana performance governance diterapkan terhadap PD-02 Architecture Office.

E6 menjawab:

> **"Siapa yang memiliki responsibility terhadap kualitas performance PD-02, siapa yang memiliki authority untuk mengelola dan mereview performance, bagaimana escalation dilakukan, dan bagaimana accountability dipertahankan?"**

E6 mencakup:

1. Performance Ownership;
2. Performance Authority;
3. Review Authority;
4. Escalation;
5. Accountability.

E6 memastikan bahwa performance PD-02 memiliki governance yang jelas tanpa mengambil alih:

- Architecture Authority;
- Governance Authority;
- Strategic Authority;
- Operational Authority;
- Domain Ownership;
- Executive Authority.

⸻
 
3. Core Governance Principle
Performance governance establishes ownership, authority, review responsibility, escalation, and accountability for managing PD-02 performance while preserving the ownership and authority of the Architecture domain being measured.
Dengan demikian:
Performance Governance
        ↓
governs performance management
        ↓
does not become Architecture Governance
Performance Governance menilai dan mengelola performance mechanism.
Architecture Governance tetap mengelola architectural authority.
 
⸻
 
4. Fundamental Boundary
Canonical distinction:
PERFORMANCE GOVERNANCE
        │
        ├── owns performance-management mechanism
        ├── governs performance review
        ├── maintains performance accountability
        ├── coordinates escalation
        └── verifies performance governance integrity
versus:
PD-02 ARCHITECTURE GOVERNANCE
        │
        ├── owns Architecture domain
        ├── owns Architecture decisions
        ├── owns Canonical Architecture
        ├── owns ADR
        ├── owns Architecture Blueprint
        └── owns Architecture Standards
Kedua layer tersebut berinteraksi tetapi tidak boleh digabung.
 
⸻

Baseline PD-02 secara eksplisit menempatkan Architecture sebagai primary organizational ownership PD-02.

Performance Owner

* performance improvement framework;

PD-02 bertanggung jawab atas:
* architecture evidence;
* architecture context;
* architecture outcome;
* architecture-related performance condition;
* architecture improvement execution apabila berada dalam mandate PD-02.

7. Performance Owner
Performance Owner memiliki ownership atas performance management capability.
Performance Owner bertanggung jawab memastikan:
* performance framework tersedia;
* measurement dapat dijalankan;
* review dapat dijalankan;
* governance dapat dijalankan;
* escalation dapat dijalankan;
* performance records dapat dipertahankan.
Performance Owner tidak mengambil alih Architecture ownership.
 
⸻
 
8. PD-02 as Domain Owner
Dalam performance assessment terhadap Architecture:
PD-02 menyediakan:
* domain evidence;
* domain context;
* architecture performance data;
* architecture condition;
* architecture interpretation;
* response proposal;
* improvement execution dalam authority-nya.
PD-02 tidak dapat menolak valid performance finding hanya karena finding tersebut tidak menguntungkan.
Sebaliknya:
Performance conclusion harus tetap berbasis evidence.
 
⸻
 
9. Performance Authority
Performance Authority berarti authority yang diberikan untuk menjalankan fungsi performance governance/review.
Performance Authority dapat mencakup:
* maintain performance governance;
* conduct performance review;
* validate evidence;
* assess performance;
* issue performance finding;
* coordinate escalation;
* verify improvement.
Performance Authority tidak berarti authority untuk:
* change Architecture;
* approve Architecture Decision;
* modify Canonical Architecture;
* modify ADR;
* change Architecture Standards;
* change PD-02 organizational boundary.
 
⸻
 
10. Performance Authority ≠ Architecture Authority
Canonical boundary:
Performance Authority
        ≠
Architecture Authority
Performance Authority dapat mengatakan:
“Architecture performance is below approved expectation.”
Architecture Authority menentukan:
“What architectural response is authorized?”
Contoh:
Performance Finding
        ↓
Architecture-related cause
        ↓
Architecture Review
        ↓
Architecture Decision
Performance Governance tidak menggantikan Architecture Governance.
 
⸻
 
11. Review Authority
Review ownership harus dibedakan dari review authority.
Role	Primary Responsibility
Performance Owner	Mengelola performance review
PD-02 Domain Owner	Menyediakan Architecture evidence/context
Reviewer	Independent validation/challenge
Executive Leadership	Menilai result dan menentukan response dalam authority
Executive Authority	Final authority untuk Performance Review sesuai baseline
Architecture Authority	Final authority untuk architectural matters
Record Custodian	Menjaga performance governance record
Baseline Performance Review menetapkan Performance Review sebagai domain dengan final authority mengikuti approved Executive Review model.
 
⸻
 
12. Review Independence
Reviewer harus memiliki independence yang proporsional terhadap:
* materiality;
* sensitivity;
* strategic importance;
* cross-platform impact;
* governance significance.
Reviewer harus dapat:
* challenge evidence;
* challenge assessment;
* challenge conclusion;
* identify limitation;
* request additional evidence.
Reviewer tidak boleh menjadi decision owner atau execution owner untuk matter yang sama apabila hal tersebut merusak independence yang diperlukan.

31. Performance Governance RACI
Logical responsibility model:
Activity	Performance Owner	PD-02 Domain Owner	Reviewer	Executive Leadership	Executive Authority
Define performance framework	A/R	C	C	I	I
Maintain KPI framework	A/R	C	C	I	I
Provide Architecture evidence	C	A/R	I	I	I
Perform assessment	A/R	C	C	I	I

Review result	R	C	C	A/R	A
Determine response	C	R/C	C	R	A
Escalate	A/R	R	C	C	A

68. Performance Governance Decision Boundary
Performance Governance may:

* maintain performance governance mechanism;
* assess performance governance condition;
* coordinate review;
* coordinate escalation;
* verify accountability;
* maintain governance records.
Performance Governance may not automatically:
* change Architecture;
* change Strategy;
* change Governance policy;
* change organizational ownership;
* override Architecture Authority;
* override Executive Authority;
* execute operational work.

69. Canonical Governance Principle
Performance governance governs the integrity of the performance management mechanism; it does not become the authority of the domain being measured.
 
⸻
 
70. Canonical Domain Preservation Principle
A performance finding concerning PD-02 does not transfer Architecture ownership away from PD-02, and a performance review does not create authority to decide architectural matters.
 
⸻
 
71. Canonical Authority Principle
Performance Authority shall operate only within explicitly delegated performance scope and shall not be interpreted as authority over Architecture, Strategy, Governance, or Operation.
 
⸻
 
72. Canonical Accountability Principle
Performance failure shall not automatically transfer accountability; accountability remains aligned to approved ownership and authority unless formally changed by the applicable authority.
 
⸻
 
73. Canonical Escalation Principle
When an unresolved performance matter exceeds current authority, it shall be escalated to an existing authority capable of resolving it; no new authority shall be manufactured to close the gap.
 
⸻
 
74. Canonical Decision Principle
A performance finding or recommendation shall not be represented as a decision unless the applicable decision authority has formally acted.
 
⸻
 
75. Canonical Architecture Interface Principle
When performance evidence identifies an architectural condition, Performance Governance shall refer the matter to the applicable Architecture Governance mechanism rather than exercising Architecture Authority itself.
